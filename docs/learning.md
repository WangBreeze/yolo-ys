# 记忆与训练

现在提供两条独立训练路径：`train` 用已验证执行轨迹生成动作经验表；`prepare-dataset` / `build-dataset` / `train-detector` 从人工复核的视频框选数据训练 YOLO 感知模型。Linux 无需游戏窗口即可完成第二条路径，具体命令见 [Linux 制作训练数据与 Windows 部署](windows-linux.md)。视频帧没有真实键鼠标签，不能作为第一条路径的成功动作经验。

## 当前已实现

教程进入 SQLite 后是 candidate。执行时记录观察状态、动作、是否确实发送、前后状态和完成结果。只有成功结束、且有已执行动作及后续步骤验证的 simulation/live 轨迹，才能导出为训练样本。dry-run、录像、失败、未正常结束和跳过已满足步骤不会冒充动作示范。

```bash
python -m game_agent demo
python -m game_agent recall 购买
python -m game_agent train
python -m game_agent --config configs/learned-demo.toml demo
python -m game_agent export --output memory/datasets/verified.jsonl
```

`train` 当前生成的是动作经验表：按目标和语义状态归组，从已验证示范中选择出现最多的动作。产物携带 game/profile、模式和来源 run；再次启动可独立加载。遇到从未学习的状态会停止，不臆造动作。示范相互矛盾时默认拒绝执行，可通过增加状态信息消歧；`min_agreement` 可配置最低一致率。这是可复现的非神经网络基线，不等于训练 YOLO、GPT-6 或跨游戏大模型。

样本结构包含 `goal`、`before`、`action`、`template`、`after`、`applied`、`run_id` 和插件来源。按钮动作模板保存目标名称，在执行时重新定位。状态中的 `__` 前缀为采集元数据，不作为经验表的语义检索键。

## 神经网络学习的扩展方向

| 阶段 | 数据与方法 | 产物 | 验证 |
|---|---|---|---|
| 感知 | 游戏画面标注，微调 YOLO/OCR | 专用感知模型 | 按游戏场次划分测试集，测召回和误报 |
| 动作示范 | 同步屏幕、原始键鼠事件和单调时钟 | 带真实动作标签的轨迹 | 对齐误差、释放事件、丢帧率 |
| 行为克隆 | 当前/历史视觉特征 + 子目标 → 动作 | policy 插件加载的模型 | 独立场次任务成功率和端到端延迟 |
| 逆动力学 | 前后帧 → 真实动作，预测录像伪标签 | 离线标注器 | 用有真值的视频评估歧义和误标 |
| 纠正学习 | 人工接管失败状态，保留恢复轨迹 | 更新后的策略版本 | 起点变化、错误恢复、版本回归 |

当前导出的是结构化状态轨迹，未实现屏幕像素/人工键鼠事件录制器；训练视觉时序策略前应新增记录这些原始观测的采集适配器。运行日志的动作是代理发出的动作，不把它们标记为人工示范。经验表失败不能通过无限重试补救，应收集新的示范或补充感知。

不从单条剪辑视频承诺复原精确按键。VPT 提供“带动作示范 → 逆动力学 → 无标签视频伪标注”的参考方法，[VPT](https://openai.com/index/vpt/)；迭代收集策略所遇失败状态对应 [DAgger](https://arxiv.org/abs/1011.0686) 的思路。

## 版本与评估约定

游戏 build、输入绑定和 UI 语义分开标识。每次训练另存产物版本，保留验证数据和来源，不把模拟器成功计入实机成功率。性能数字必须指明模式、分辨率、模型、冷/热启动、样本数量及计时范围；尤其不能用模拟 tick 或 YOLO 单模型耗时代表实机完整延迟。

项目记忆在 `memory/` 下，默认被 Git 忽略。备份数据库时关闭程序后复制，或使用 SQLite backup API；运行中不要只复制主文件而遗漏 WAL。导出 JSONL 用于人工查看和训练接口接入，SQLite 为权威记录。
